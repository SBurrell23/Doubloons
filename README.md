# Doubloons!

A pirate gem-trading game for two to four captains, played in the
browser on a small table on a desert island. Peer to peer — there is no
game server, just a handshake and then a direct connection between
players.

**Play it: https://sburrell23.github.io/Doubloons/**

The rules are Splendor's, unchanged. The flavour is not.

---

## The game in one minute

Take gems. Gems buy cards. Every card you buy grants a permanent
**bonus** of its colour, which comes off the price of every future card
of that colour, forever — so cheap cards early buy expensive ones later.
Cards are worth **infamy**; so are the Pirate Lords, who join you for
free the moment your bonuses meet their demand.

First captain to 15 infamy triggers the final round. Highest total wins;
ties go to whoever bought *fewer* cards.

On your turn you do exactly one of:

| Action | What it does |
| --- | --- |
| Take three gems | One each of three different colours |
| Take two gems | Two of one colour, only if four or more remain |
| Stow a card | Reserve it so nobody else can buy it, and take a doubloon |
| Buy a card | Pay its cost, minus your bonuses |

Ten tokens in hand at the end of a turn, three cards in your hold. The
in-game **How to Play** has the illustrated version.

## Playing with other people

One player hosts and gets a four-character room code; everyone else
types it in, or follows the invite link. The host's browser owns the
rules and broadcasts the state — clients only ever send intents, so
nobody can make an illegal move by editing their own copy. Blind-stowed
cards stay hidden from everyone else.

If somebody drops mid-game, their seat keeps playing — the crew covers
for them — so the table never stalls.

You can also add computer captains at three difficulties, or play a solo
game against them with no connection at all.

## Everything here is generated

There is exactly one asset file in this project: the background music.
Everything else is made at runtime.

- **Textures** — sand, wood, bark, rock, all ninety card faces and the
  Pirate Lord tiles are painted with Canvas2D (`src/three/textures.js`).
- **Card art** — every one of the ninety cards has its own drawn
  illustration, in an engraved-woodcut hand, as a Canvas2D function
  (`src/three/cardart/`). No two are alike.
- **Geometry** — the island, the palm, the crabs, the rocks, the chest
  and the cut gems are built from code (`src/three/props.js`).
- **Sound** — every effect is synthesised with WebAudio oscillators and
  filtered noise. No sample files (`src/audio/sfx.js`).
- **Icons** — hand-drawn SVG paths (`src/ui/icons.js`). No emoji.
- **The cursor** — a gold arrow, drawn as SVG (`src/ui/cursor.js`).

## Running it

```bash
npm install
npm run dev
```

Then open http://localhost:5173. To test multiplayer, open a second tab
and join the room code from the first.

```bash
npm run build      # production build into dist/
npm run preview    # serve that build
```

### Checking the rules

The rules engine is pure and has no DOM or Three.js dependency, so it
can be exercised headlessly:

```bash
node scripts/simulate.mjs 300
```

That plays several hundred complete AI-versus-AI games and asserts the
invariants after every single action: gem and gold conservation, all
ninety cards accounted for exactly once, the ten-token and three-card
limits, and that the board refills while a deck has cards. It also
reports the distribution of game lengths.

```bash
node scripts/ai-ladder.mjs 400
```

Plays the three AI levels head to head in both seatings, to confirm the
difficulty ladder is actually monotonic.

## How it fits together

```
src/
  game/
    data.js        the 90 cards and 10 Lords, generated by rotating
                   Splendor's cost patterns around the colour ring
    rules.js       pure rules engine — validate(), apply(), viewFor()
    ai.js          heuristic opponents; the top level does a one-ply
                   search over the position it would leave behind
    session.js     host/client/solo sessions, turn clock, AI driver
  net/net.js       PeerJS transport, host-authoritative
  three/           scene, island props, board, procedural textures
  ui/              title, lobby, HUD, settings, guide, tooltips, icons
  audio/           synthesised effects and the music loop
```

The host holds the only authoritative state. `viewFor(state, playerId)`
produces a per-player snapshot with other people's blind reserves masked
out, so hidden information never reaches a client that should not have
it.

### A note on the deck

Splendor's ninety cards are not arbitrary: each colour gets the same set
of cost *shapes*, rotated around the five-colour ring. `data.js` encodes
the shapes once and generates all ninety, which is why the economy is
balanced without a hand-typed table to get wrong.

## Moving the camera

Left-drag slides the view across the island, right-drag (or shift-drag)
swings it round, and the wheel moves in and out. `W A S D` or the arrow
keys slide, `Q`/`E` swing, `+`/`-` zoom, and `Space` returns you to the
table. No letter the camera uses is bound to a panel. The full list
lives under Settings → Controls.

## Settings

Reachable anywhere with the cog, or <kbd>Esc</kbd> when nothing else is open.

- **Sound** — master, effects, music and ambience levels; mute
- **Graphics** — frame cap, antialiasing, shadows, resolution scale,
  ocean detail, field of view, wildlife, FPS readout
- **Gameplay** — tooltips, purchase confirmation, affordability
  highlighting, animation speed, colour-blind gem labels
- **Controls** — the camera and keyboard reference

Lobby options include the infamy target, a turn timer (which auto-plays
a sensible move when it expires), AI speed, open holds, and a house rule
for extra doubloons.

## Deployment

Pushing to `main` runs the rules simulation, builds, and publishes to
GitHub Pages via `.github/workflows/deploy.yml`. The Vite `base` is set
from the `GITHUB_PAGES` environment variable so the same source works at
a domain root or under a repository sub-path.
